# Protected write paths

29 October 2026. Header Editor 1.0.1, Focal Length Blend 0.11.8 and RGB DualBand 0.15.0 use the shared `ProtectedPaths.jsh`. Keep that file beside the JavaScript scripts. Astrometric Solution Copy 1.1 has no direct disk writer and is unchanged.

Before disk writes the guard resolves existing POSIX symbolic links, including directory aliases, and compares complete directory boundaries against the running application's documented `CoreApplication.baseDirPath`, `configDirPath` and `appDirPath`. Comparison is conservative, case folded and Unicode NFC normalized when available. Nonexistent child destinations are checked through existing ancestors. Parent-directory segments, invalid paths, ambiguous Windows names (including short-name aliases and reserved device names) and Windows redirection/reparse points are refused. Existing file hard links are rejected when their count is reported by the platform. Missing protected-root information stops writing.

Coverage: sample destination validation occurs before transfer; temporary and publication paths are checked again. Header destinations, temporary images, original replacement and backup paths are checked, as is the direct FITS writer. RGB help-text export writes a new peer file and replaces the destination by rename through the guarded text writer, retaining/restoring the previous file on publication failure. It does not truncate an existing destination in place. Configuration persistence through Settings remains allowed and unchanged. The whole installation and configuration directories are protected conservatively, including the developer's own installed files. Ordinary user folders and safe resolved POSIX folder aliases remain usable. The header editor retains its pre-existing stricter input-link policy.

Native validation on PixInsight 1.9.6 x64/macOS: 10 guard/download checks plus 4 legacy-header protection checks passed. Installation/configuration targets, case aliases, traversal, directory symbolic links into the installation and file hard links were rejected without writes to protected paths. A protected download target was rejected before its transfer callback. User text output, verified download replacement and same-size tamper rejection passed. Seven FITS/XISF I/O regression checks also passed, plus the RGB/SPCC settings interfaces. The download/hash Node suite passed 12 tests with the actual published sample ZIP. Windows/Linux native behavior was not exercised in this session; the Windows reparse policy is intentionally conservative.

This is application-level validation of the running installation and configuration roots, not a claim to prevent hostile concurrent filesystem mutation or to discover every other PixInsight installation. It does not request administrator privileges, modify security preferences, sign code or create an updater. Image-processing algorithms are unchanged. The broader review retains its SPCC/fresh-solve limits; StarX has subsequently passed the native follow-up in starx-validation-1.9.6.md.
